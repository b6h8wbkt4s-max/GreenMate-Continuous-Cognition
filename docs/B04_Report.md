# B04 交付报告：轻量级 RAG（知识检索问答）

## 功能

### 知识库

[knowledge/](../knowledge/) 目录下 3 个 txt 文件（假资料），共 15 个 chunk：

| 文件 | 内容 |
|---|---|
| `01_tomato_temperature.txt` | 番茄各生长阶段适宜温度（发芽 20-30°C、幼苗 15-25°C、开花坐果 20-28°C、果实膨大 22-26°C 等） |
| `02_tomato_humidity.txt` | 番茄各阶段适宜空气湿度与土壤含水量（苗期 60%-70%、开花 55%-65%、高于 85% 易发灰霉病/晚疫病等） |
| `03_tomato_management.txt` | 温湿度协同管理要点（高温低湿坐果率下降、遮阳增湿、冬季控水、温湿度波动致裂果等） |

刻意不包含施肥内容，用于验证「资料不足」路径。

### 检索模块 [rag.py](../rag.py)

- `load_knowledge()`：按段落（空行）切分成 chunks，带来源文件名与段号。文件首行标题（无句末标点）不参与检索——短文本在 TF-IDF 中得分虚高，实测发现后修复。
- `retrieve(query, k=2)`：字符二元组 TF-IDF + 余弦相似度，返回最相关的 2 个 chunk。纯标准库实现，无向量数据库、无新增依赖。
- `build_rag_prompt(question, top_chunks)`：检索结果拼成 `[1] 来源：xxx（第N段）` 格式的参考资料，并要求大模型：必须根据参考资料回答并注明来源编号；资料不足时只能回答「资料不足」，不得编造。

### 接口与页面

- `POST /rag`：body `{"question": "..."}`，返回 `{question, sources, answer}`；空问题 400，LLM 失败沿用既有错误处理（502 + 明确错误信息）。
- 页面新增「专业知识问答（RAG）」区：输入框（支持回车）+ 提问按钮；回答卡片展示问题、检索命中来源、回答。

## 测试结果（真实 LLM 调用）

| 问题 | 检索命中 | 回答 | 结论 |
|---|---|---|---|
| 番茄开花期适宜多少温度？ | 03 第2段、01 第4段 | 「白天 20-28°C，夜间 15-20°C [2]」 | 正确且注明来源 ✓ |
| 番茄怎么施肥？ | 命中无关的湿度段落 | 「资料不足」 | 没有编造 ✓ |

| 夜间多少度有利于番茄转色？（检索单元测试） | 03 第6段、01 第5段 | — | top-2 精准 ✓ |

## 局限性（如实记录）

- **同义改写问题召回不佳**：「空气湿度太高会得什么病」这类问题，关键词检索排名不理想——「得什么病」与文中「灰霉病/晚疫病」字面不重叠，直接答案段落排不进 top-2。此时大模型按规则回答「资料不足」而非编造，行为诚实但召回失败。
- 这是无向量检索的固有边界。若后续要提升召回，方向：
  1. 引入 jieba 分词做词级检索（成本低）；
  2. 换 embedding + 向量相似度检索（需新增依赖或向量库）。
